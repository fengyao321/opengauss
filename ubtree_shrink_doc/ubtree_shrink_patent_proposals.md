## 二、 专利提案 1：基于 Lehman-Yao 协议的两阶段解耦 B-Link 树在线页搬迁方法及系统

### 2.1 技术领域
本发明属于数据库存储引擎与并发控制技术领域，尤其涉及一种关系型数据库中 B-Link 树索引在高并发读写负载下的在线物理页迁移与拓扑重定向方法。

### 2.2 背景技术与技术问题
- **技术缺陷**：传统 B-Tree 索引页面搬迁/压缩操作通常需要同时持有父节点、待迁移节点、左右兄弟节点的写锁。
- **致命缺陷 1（AB-BA 死锁）**：搬迁事务跨层自上而下持父锁请求子锁，同层向左反向锁定左兄弟；而并发树分裂（`_bt_split`）自底向上扩展、同层自左向右加锁，极易产生循环等待引发死锁；
- **致命缺陷 2（长时阻塞）**：跨层长时间锁定 4~5 个核心数据块，造成前台高并发业务出现剧烈读写毛刺。

### 2.3 核心技术方案（发明点）
1. **阶段一（同层横向拓扑迁移）**：
   - 加锁顺序严格单向化：`left -> victim -> right -> targetFree`，**全程不获取父节点写锁**；
   - 增加左节点顺向右移校验（Step-Right），自动适应并发页面分裂；
   - 引入 Lehman-Yao 转发指针机制：在原子临界区内将被搬迁页（Victim）标记为已删除（`BTP_DELETED`），并将其右兄弟指针 `btpo_next` **强行指向目标新块 `targetFreeBlk` 作为转发指针（Forwarding Pointer）**；
   - 写入仅包含同层 4 块差量变更的增量 WAL（`XLOG_UBTREE2_SHRINK_MOVE_LEAF`），立即释放所有叶子写锁；
   - 并发只读事务即使通过父节点旧 Downlink 读到 Victim 页，感知到 `BTP_DELETED` 后自动顺着 `btpo_next` 透明跳往目标新块继续扫描，保证**零数据丢失、零查询阻塞**。
2. **阶段二（父节点 Downlink 异步修正）**：
   - 释放全部叶子锁后，自底向上重新通过扫描键定位父节点，单独持有父节点写锁；
   - 若父节点在阶段一期间发生并发分裂，顺着 `btpo_next`（`_bt_moveright`）横向检索定位，将旧块 Downlink 原位原子修正为新块；
   - 写入单块独立父节点 WAL（`XLOG_UBTREE2_SHRINK_UPDATE_PARENT`），完成解耦更新。

```
[阶段 1: 叶子层横向重定向 (严格自左向右加锁，不持有父锁)]
  1. leftBuf -> victimBuf -> rightBuf -> newBuf 严格单向加锁
  2. victimPage->btpo_flags |= BTP_DELETED
  3. victimPage->btpo_next = newBlk (转发指针)
  4. 提交并立即释放全部 4 把叶子锁
                  │
                  ▼ (并发查询读到 victim 时自动顺着 btpo_next 透明跳至 newBlk)
[阶段 2: 父节点 Downlink 修正 (自底向上独立写事务)]
  1. 自底向上检索定位 parentBuf
  2. 若父节点并发分裂，顺向 moveright 找到目标父页
  3. 修改 Downlink 指向 newBlk，持久化单块 WAL 并释放父锁
```

### 2.4 拟保护的权利要求构想
- **主权利要求（方法权项）**：
  一种面向 B-Link 树索引的数据页在线迁移方法，其特征在于，将单页迁移拆解为两个相互解耦的独立阶段：
  第一阶段仅对同层前驱页、待迁移页、后继页及空闲目标页依次施加单向写锁，将被迁移页标记为逻辑删除状态并将其向后指针设置为目标页块号作为转发指针，更新前后邻居拓扑并持久化同层增量日志后释放所有同层写锁；
  第二阶段自底向上寻址所述被迁移页的父节点并获取单个父节点写锁，根据转发关系将父节点中的下向指针更新为所述目标页块号。
- **从属权利要求**：
  - 针对并发分裂自适应向右单向顺移（Step-Right）校验机制；
  - 针对并发只读扫描依据 `BTP_DELETED` 状态与转发指针自动跳转的无损遍历机制。

### 2.5 技术效果
- 从数学图论上消除了跨层逆序持锁构成的 AB-BA 死锁环；
- 将单页迁移的多页长事务降级为微秒级短写事务，高并发读写业务吞吐零损耗。

## 三、 专利提案 2：面向多版本 B-Link 树的非叶子内部节点自底向上分层搬迁方法及系统

### 3.1 技术领域
本发明属于关系型数据库存储管理领域，涉及一种多版本 B-Link 树索引非叶子内部节点在线物理搬迁与全树物理截断实现技术。

### 3.2 背景技术与技术问题
- **技术缺陷**：B-Link 树索引扩张时，非叶子内部节点（Internal Page，Level $\ge 1$）会被追加分配在文件高物理块号区域。
- 传统收缩算法仅能搬迁叶子节点，尾部只要残存 1 个非叶子内部节点，文件物理截断水位线（`targetMaxBlock`）即被硬性拦截，**整树可物理回收空间归零**；
- 若盲目搬迁内部节点，由于内部节点 Offset 2 为负无穷占位项、最右节点无 High Key，无法通过常规键值检索定位其父节点；上下层交叉乱序搬迁更会导致子树断裂与死锁。

### 3.3 核心技术方案（发明点）
1. **严格自底向上（Strict Bottom-Up）分层推进协议**：
   - 引入分层搬迁控制流：由底层向顶层按层推进：`Level 0 -> Level 1 -> ... -> Level maxLevel - 1`；
   - 规定当且仅当下层所有活跃节点完成物理搬迁并进入稳定拓扑后，才启动上一层内部节点的搬迁，杜绝上下层交叉迁移动作引发的死锁与悬空引用；
2. **根节点物理锚定不变式（Root Anchoring）**：
   - 引入根节点绝对防护屏障：针对 `P_ISROOT` 节点，强制禁止物理平移，保证整树入口物理位置稳定，规避并发 Backend 私有缓存失效读越界风险；
3. **非叶子节点反向拓扑映射与父节点确定性寻址**：
   - 针对无 High Key 最右节点与负无穷首项，通过节点内部子页面 Downlink 拓扑关联确定性定位父节点；
4. **统一物理块平移 WAL 协议复用**：
   - 证明并实现内部节点与叶子节点底层物理数据块平移日志格式的统一性，上层控制流解耦。

### 3.4 拟保护的权利要求构想
- **主权利要求**：
  一种多版本 B-Link 树非叶子节点在线物理搬迁方法，包括：
  识别待截断高位物理区间内处于非根状态的非叶子内部节点及其所在逻辑层级；
  以严格自底向上分层递增的顺序，先执行完低层级节点的迁移并更新其拓扑，再对高层级内部节点执行定向搬迁；
  将待迁移内部节点的数据物理平移至低位空闲块，并维护其同层横向双向指针与上层父节点下向指针。
- **从属权利要求**：
  - 树根节点（Root）禁止搬迁与物理锚定保护机制；
  - 针对最右无键（Rightmost）内部节点的非键值确定性父节点寻址算法。

### 3.5 技术效果
- 彻底破解了高位非叶子内部节点阻断文件截断的业界难题；
- 使高频膨胀场景下的索引物理压缩率从 0% 突破提升至 **78%~89%**。

## 四、 专利提案 3：数据库索引在线物理截断中的边界悬空指针闭合方法及装置

### 4.1 技术领域
本发明属于数据库存储引擎高可靠性技术领域，涉及一种在数据库索引在线物理文件截断（`ftruncate`）时防止并发读穿 EOF 越界崩溃的边界自愈防护方法。

### 4.2 背景技术与技术问题
- **技术缺陷**：在将磁盘物理空间即时归还操作系统的在线截断过程中，分界线之下的存活节点右指针（`btpo_next`）仍残留记录着历史右兄弟（已被物理截断的高位块）。
- 当并发范围查询或向右遍历扫描行进至截断边界时，顺着残留指针访问已被操作系统截断的文件偏移，导致操作系统返回读取 0 字节，抛出 `read only 0 of 8192 bytes`，引发**数据库内核致命 Panic 与事务崩溃**；
- 另外，会话本地私有元页缓存（`rd_amcache`）若缓存了截断区的高位快速根节点（`btm_fastroot`），也会产生越界 Panic。

### 4.3 核心技术方案（发明点）
1. **截断前边界兄弟横向链表闭合机制（Boundary Sibling Closure）**：
   - 在执行底层物理文件截断前，反向探查待截断区间前置页面及截断分界线处的反向指针（`btpo_prev`）；
   - 准确定位所有位于截断分界线之下、但其 `btpo_next >= targetMaxBlock` 的边界页面；
   - 在截断前原子加锁，将其 `btpo_next` 强制闭合设置为终止标识 `P_NONE`（合法成为新的 `P_RIGHTMOST` 页面），并记录增量 WAL 持久化；
   - 对临界边界页面（`targetMaxBlock - 1`）实施二次防御性断言校验；
2. **元页 Fastroot 降级与会话私有缓存协同失效**：
   - 检查元页中的 `btm_fastroot`，若其块号落入截断区间，主动将其安全平滑降级回退至全局根节点 `btm_root` 并持久化 WAL；
   - 主动强制释放并失效当前会话的 `rd_amcache` 与 `rd_rootcache`，触发重新装载。

```
[截断前状态]
  Block 436 (存活活跃页) ──────btpo_next──────► [Block 437] (空闲尾部页，将被物理截断)
                                                       ▲
                                                       │ 截断分界线 (targetMaxBlock=437)
                                                       ▼
[边界闭合修复 UBTreeCloseBoundarySiblingsBeforeTruncate]
  Block 436.btpo_next 强制置为 P_NONE (成为合法的 P_RIGHTMOST) ➔ 写入增量 WAL
                                                       │
                                                       ▼
[物理截断 RelationTruncate] 操作系统安全截断至 437 块，并发扫描遍历到 436 判定链表终止，0 越界！
```

### 4.4 拟保护的权利要求构想
- **主权利要求**：
  一种数据库索引物理截断前边界悬空指针闭合方法，其特征在于包括：
  在执行底层物理文件截断前，定位所有位于物理截断分界线以内但其横向向前指针指向分界线以外目标截断区间的边界数据页；
  在物理截断前将各所述边界数据页的向前指针修改为链表终止标识，并持久化预写日志；
  完成指针闭合后，调用文件截断接口释放分界线以外的物理存储空间。
- **从属权利要求**：
  - 边界前驱页面 `btpo_prev` 反向探测与二重断言校验算法；
  - 元页 `btm_fastroot` 越界检测与回退降级及私有缓存失效联动方法。

### 4.5 技术效果
- 彻底根除了在线截断过程中的 `read beyond EOF` 崩溃漏洞；
- 达成长时间超高并发压测下 **0 Panic、0 崩溃、双向扫描 100% 绝对一致**。

## 五、 专利提案 4：基于引用计数屏障与微秒级锁升级的无锁感索引物理截断方法

### 5.1 技术领域
本发明属于数据库事务处理与存储缓冲管理领域，涉及一种利用 Buffer Pool 引用计数屏障与瞬时锁升级实现业务零感知的物理空间截断方法。

### 5.2 背景技术与技术问题
- **技术缺陷**：传统数据库物理空间收缩依赖全局长事务持有最高表级排他锁（`AccessExclusiveLock`），造成业务数十秒至数分钟停机；
- 若为了并发而在弱锁下强行截断，并发读事务可能已在 Buffer Pool 中固定了待截断块的内存页面（Pin Count > 0），物理截断会导致读写脏页写穿越界、内核崩溃或内存访问冲突。

### 5.3 核心技术方案（发明点）
1. **轻量意向锁下全流程搬迁**：
   - 索引收缩全流程（包括状态探测、代价评估、分层页搬迁）均在非阻塞的意向排他锁（`ShareUpdateExclusiveLock`）下执行，前台并发 `SELECT/INSERT/UPDATE/DELETE` 完全正常运行；
2. **微秒级短暂锁升级与快速退避策略**：
   - 仅在最终调用 `ftruncate` 的瞬间，尝试获取极短时间的 `AccessExclusiveLock`（超时门限仅 200ms），获取失败立即主动退避放弃本轮截断，前台业务无任何锁卡顿；
3. **Buffer Pool Pin-Count 物理安全屏障检测（Safety Barrier）**：
   - 升级获得排他锁之后、调用底层 `RelationTruncate` 之前，遍历系统共享缓冲池扫描属于目标截断区间 `[targetMaxBlock, currentTotal)` 的 Buffer 描述符；
   - 检查 `BUF_STATE_GET_REFCOUNT(buf_state) != 0`：若检测到任何并发后台会话仍持有引用计数，**立即主动释放排他锁并安全退避**，终止截断，确保没有未决 IO。

### 5.4 拟保护的权利要求构想
- **主权利要求**：
  一种数据库索引在线无锁感物理截断方法，其特征在于包括：
  在非阻塞弱表锁保护下并发执行索引分析与数据页定向迁移；
  在需要执行物理文件截断时，瞬时申请升级为强排他表锁，并设置超时退出门限；
  在获得强排他表锁后且在调用物理截断前，遍历缓冲池检测待截断物理块区间内是否存在被并发线程固定的非零引用计数页面；
  若存在非零引用计数页面，则主动释放强排他表锁并终止本次截断操作；
  若不存在，则调用文件截断接口缩减物理文件大小。

### 5.5 技术效果
- 将传统空间收缩所需的数分钟停机窗口缩减为 **0 业务停机（微秒级瞬态锁）**；
- 严格杜绝了脏页刷盘 Panic 和并发后端野指针读写。

## 六、 专利提案 5：面向主备复制架构的索引回收队列水位同步与日志解耦方法

### 6.1 技术领域
本发明属于分布式数据库与高可用容灾技术领域，涉及一种在主备流复制环境下保障空闲页回收队列与物理截断强一致性的日志协同方法。

### 6.2 背景技术与技术问题
- **技术缺陷**：主库执行索引物理截断并清理了内存中高位块，但若未对空闲回收队列（URQ）的高位块清理记录日志，备库回放时仅截断了物理文件，其 URQ 中仍残留着高位物理块号；
- 一旦发生故障倒换（Failover）备库升主，新主库会从 URQ 中分配高位块号，导致**索引文件产生巨大物理空洞甚至数据覆盖损坏**；
- 另外，若将页迁移涉及的 5 块数据合并为单条巨型 WAL 且强制整页刷盘，会导致备库并行回放（Parallel Redo）时产生全局跨 Worker 屏障阻塞。

### 6.3 核心技术方案（发明点）
1. **URQ 物理水位同步专属日志机制（`XLOG_UBTREE2_URQ_PURGE`）**：
   - 主库在物理截断前生成并持久化携带截断目标块号 `targetMaxBlock` 的独立 WAL 记录；
   - 备库在 Redo 重放时，构建虚拟 Relcache 上下文，对称调用队列清理逻辑，精准遍历并剔除所有高于截断线的高位块槽位，彻底消除 Failover 升主空洞；
2. **跨层级日志解耦与增量日志压缩**：
   - 将页搬迁日志彻底拆解为：同层 4 块差量日志（`SHRINK_MOVE_LEAF`）与单块父节点独立日志（`SHRINK_UPDATE_PARENT`）；
   - 移除整页强制镜像刷新（`REGBUF_STANDARD` 替代 `REGBUF_FORCE_IMAGE`），解除备节点多线程并行回放时的跨层级全局 Barrier，大幅提升备库回放吞吐。

### 6.4 拟保护的权利要求构想
- **主权利要求**：
  一种主备复制环境下索引回收队列水位同步方法，其特征在于包括：
  主节点在执行索引物理文件截断前，记录包含目标截断水位线块号的队列清理专用预写日志；
  主节点在本地物理截断前清理空闲回收队列中高于所述水位线的数据块槽位；
  备节点在重放所述队列清理专用预写日志时，在备节点端对称遍历并清理其本地空闲回收队列中高于所述水位线的数据块槽位。
- **从属权利要求**：
  - 同层横向 4 块差量 WAL 与跨层父节点单块 WAL 异步解耦重做机制。

### 6.5 技术效果
- 保障了主备物理文件与元数据回收队列的 100% 绝对一致；
- 彻底杜绝主备切换升主后文件空洞与元数据错乱；解除并行回放屏障。

## 七、 专利提案 6：基于边际效益衰减与轻量探查的索引自适应收缩调度方法及系统

### 7.1 技术领域
本发明属于智能数据库自治运维（AI4DB / Self-Driving DB）领域，涉及一种基于成本效益模型与防颠簸熔断的索引在线收缩自适应调度方法。

### 7.2 背景技术与技术问题
- **技术缺陷**：若周期性盲目对活跃写入的索引发起物理收缩，在高并发追加写场景下，全量扫描索引会导致 CPU 和 Buffer 锁剧烈争抢，业务吞吐跌落 40% 以上；
- 盲目将尾部页搬迁至低位会导致低位页立刻发生并发分裂，形成“收缩-分裂-再收缩”的剧烈颠簸对抗（Compaction Thrashing）。

### 7.3 核心技术方案（发明点）
1. **毫秒级只读轻量探查（Fast Diagnostic Probe）**：
   - 提供微秒级只读探查接口（`gs_ubtree_shrink_check`，实测耗时仅 ~1.98ms），通过快速反向尾部探测预估待截断块数与搬迁代价比；
   - 引入成本收益门限（`CostRatio = VictimCount / FreedGain <= 0.5`），若不满足条件极速早退，过滤 90% 以上的无效调用；
2. **边际效益衰减与防颠簸自适应熔断（Thrashing Guard）**：
   - 在多轮迭代搬迁循环中，动态跟踪单轮搬迁获得的净释放增量；
   - 当单轮增量边际收益低于保护门限（如释放收益率 < 20%）时，判定系统进入并发分裂对抗状态，立即主动熔断跳出，**确保业务 TPS 零损耗**。

```
                         gs_ubtree_shrink_check (轻量探查 ~1.98ms)
                                           │
                        ┌──────────────────┴──────────────────┐
                        ▼                                     ▼
             未达到成本收益门限 (Cost>0.5)           满足收缩收益 (Cost<=0.5)
                        │                                     │
                        ▼                                     ▼
                 【极速退出 0 损耗】                    启动分层迭代页搬迁
                                                              │
                                                              ▼
                                                   单轮边际效益是否 < 20%?
                                                              │
                                            ┌─────────────────┴─────────────────┐
                                            ▼                                   ▼
                                      是 (检测到对抗颠簸)                  否 (稳步释放)
                                            │                                   │
                                            ▼                                   ▼
                                   【自适应熔断退出】                   继续推进至安全截断
```

### 7.4 拟保护的权利要求构想
- **主权利要求**：
  一种数据库索引自适应在线收缩方法，其特征在于包括：
  在发起物理收缩前，通过轻量级只读反向探查计算索引尾部可截断块数与需迁移活跃块数的成本收益比；
  当成本收益比满足预设阈值时触发迭代页迁移；
  在迭代页迁移过程中，动态监测每轮迁移带来的物理空间净释放增量；
  当单轮净释放增量低于预设边际效益门限时，主动触发熔断机制终止收缩操作。

### 7.5 技术效果
- 生产环境 TPC-C 测试中，过滤掉 90% 以上无效收缩调用，实现业务 TPS 零损耗；
- 有效遏制单调膨胀，达成资源利用与空间释放的最优平衡。
